# Задача: проверять шейдеры теми DEFINE, с которыми их грузит движок

Репозиторий: `SVar-Solo/ToW_Rearmed_shaders`.
Исполнителю: у тебя уже есть `tools/compile_shaders.py` и CI `.github/workflows/shader-check.yml`
(матрица SM4/SM5, 154 цели, зелёный прогон). Нужно расширить их так, чтобы проверялись
**варианты**, а не только базовые сборки.

Истина по дефайнам — репозиторий `SVar-Solo/ToW_Rearmed_core_dll`, файлы `*.cpp` там
авторитетнее любых наших догадок. Ссылки `файл:строка` ниже — оттуда.

---

## 1. Почему это не косметика

**1.1. Сейчас в CI нет ни одного дефайна.** `HLSL_D3D11/Shaders.json` — 154 цели, у всех
`{"source", "stage", "entry", "output"}` и **ни одной** записи с дефайнами. Всякий код под
`#ifdef` в CI не компилируется никогда.

**1.2. А движок просит варианты.** `halShader_D3D11` разбирает строку `-D SHADOW -D COMPAREZ …`
и передаёт макросы в `D3DCompile` (`HAL/HALShader_D3D11.cpp:711`, `BuildDefines`). В порте условные блоки есть в **82 файлах** из 149; дефайны от движка получают 72 из них.
Например, под `USE_SHADOWS` — 14 файлов, под `SHADOW` — 9.

**1.3. Отсюда реальный баг, который CI не увидел.** `MegaPlanePS.hlsl:304`:

```hlsl
#ifdef SHADOW
	float shadow_factor = gbuffer.r;
	ndl *= shadow_factor;
#endif
```

Этот вариант — единственный, который вообще читает тени по экрану. У пользователя сейчас
в логе `shadow probe: red 0.000, zero in 100 % samples` — то есть ландшафт целиком уходит в
ambient: «трава и ближний ландшафт чёрные, дальний — ок, но без затенений на склонах».
`SHADOW`-вариант `MegaPlanePS` **ни разу не компилировался в CI**. Оттуда же берутся
«пехота рендерится только туманом»: если fog-вариант не собирается, движок молча уходит
на фолбэк, и картинка перестаёт соответствовать коду.

**1.4. `SpeedTreeDefaults.hlsli` маскирует проблему.** Он определяет `NUM_WIND_MATRICES`,
`MAX_NUM_LEAF_ANGLES`, `USE_FOG`, `INTERMEDIATE_FRONDBRANCH_FADING` и не только — поэтому
«базовая» сборка SpeedTree-шейдеров выглядит как успешная, хотя приходит в другой
конфигурации, чем в игре. Ниже, в §4, про `INTERMEDIATE_FRONDBRANCH_FADING` отдельно.

## 2. Что именно передаёт движок

Полная таблица — готовый файл **`docs/shader_engine_defines.json`** из
`core_dll` (78 КБ, 381 запись): массив `{"source": "MegaPlanePS.hlsl", "defines": [...]}` плюс
`"always": ["SM40=1"]`. Его можно взять как есть — см. §3, требование R1.
Сгенерирован скриптом `core_dll/tools/gen_engine_defines.py` из `Shaders.json` и правил
ниже; при изменении правил перегенерировать.

Ключевые правила и их источник:

| Файлы | Дефайны | Откуда |
|---|---|---|
| `MegaPlaneVS/PS` | 32 набора: `CLIPPING`, `USE_NOISE`, `USE_FOG`, `USE_BUMP` — все сочетания (4 бита), каждый с `SHADOW COMPAREZ` и без | `Clouds/CumulusClouds.cpp:1205` — битовая маска `opshad` |
| `ObjectsOnePassVS/PS` | `USE_SPECULAR USE_SHADOWS` и то же + `USE_SKINNING` | `render/rendman.cpp:1002` |
| `ObjectsZPassVS/FS`, `ObjectsDepthPassVS/PS` | пусто и `USE_SKINNING` | `render/rendman.cpp:1108`, `:1180` |
| `SpeedTree/*` (50 целей) | базовый набор + `USE_FOG` + `SUPPORT_360_BILLBOARDS` + оба | `SpeedTree2/SpeedTreeForest.cpp:3714` |
| `TreeVP` | `SHADOW`; `SHADOW FOG`; `FOG`; `ZPASS` | `landscape/TreeProp.cpp:3448`, `:3489`, `:3558`, `:3585` |
| `TreeFP` | то же, но `SHADOW` всегда с `COMPAREZ` | там же |
| `TreeTrunkVS/PS` | пусто; `FOG` | `landscape/TreeProp.cpp:3602`, `:3611` |
| `RoadVP` | `SHADOW SPECULAR FOG`; `SPECULAR FOG`; `SPECULAR COMPAREZ` | `landscape/DeformationManager.cpp:181`, `:221`; `effects3d/trackeff3d.cpp:220` |
| `RoadFP` | `SHADOW SPECULAR COMPAREZ FOG`; `SPECULAR FOG`; `SPECULAR COMPAREZ` | там же |
| `GrassMainPassVS/PS` | `FULL`; `FULL COMPAREZ` | `landscape/Grass.cpp:325` |
| `GrassDepthPassVS/PS` | `FULL` | `landscape/Grass.cpp:343` |
| `FogTest` | `SIMPLE_FOG` | `landscape/Fog.cpp:545` |
| `EffectShader2VS/FS` | `SOFT_PARTICLES` | `effects3d/MetaEffect.cpp:4542` |
| всё остальное | без дефайнов | `HDRMainVS`, `WaterVS/PS`, `Sun*`, `SkyCube*`, пост-эффекты |

Три факта, которые легко перепутать:

* **`SM40=1` добавляется всегда** — `HAL/HALShader_D3D11.cpp:716`, первой строкой
  `BuildDefines`. Ни один файл порта `SM40` не использует, но для верности пусть будет.
* **`HS_SHADERS_NV` в D3D11 всегда `FALSE`** (`HAL/THALDevice_D3D11.cpp:2293`), поэтому
  `SHADOW` **всегда** идёт с `COMPAREZ`. Вариант «`SHADOW` без `COMPAREZ`» нужен только
  для `TreeVP`, где движок и так передаёт его без `COMPAREZ`.
* **`USE_SHADOWS` для `ObjectsOnePass` включён всегда** — `render/rendman.cpp:994`,
  `bool b_shadows = true;` (заглушка автора, не баг). А `USE_FOG` для этих же файлов —
  **никогда**: `bool b_fog = false;` на строке ниже.

Отдельно: **`DeformationVP/FP.hlsl` в этой сборке не загружаются вообще.** Деформацию
ландшафта движок грузит из `RoadVP/RoadFP` (`landscape/DeformationManager.h:23`). Файлы
пусть остаются, но дефайны им не нужны — собирай как есть.

## 3. Требования к скрипту и манифесту

**R1. Манифест должен уметь дефайны.** Либо расширить `Shaders.json`: у цели появляется
необязательное `"defines": ["SHADOW", "COMPAREZ"]`, и одна и та же `source` встречается
несколько раз с разными наборами (так уже работает `SMAA_Passes.hlsl` с восемью точками
входа — механизм есть, надо только разрешить дефайны). Либо положить рядом
`EngineDefines.json` формата из §2 и научить скрипт его читать. Первое лучше: одна точка
истины, одна валидация, и наш оверлей видит то же самое.

**R2. Прогон по умолчанию должен включать варианты.** Сейчас `python tools/compile_shaders.py
HLSL_D3D11` собирает 154 базовые цели. После доработки — **381 цель** (базовые + варианты;
на SM4; на SM5 умножать на два не обязательно, см. R7). Именно это число — приёмочный
ориентир. Базовые сборки оставить: они дешевле и ловят ошибки в общем коде.

**R3. Недопустима склейка наборов.** Нельзя собирать один шейдер с объединением всех
дефайнов: `#ifdef SHADOW` + `#ifdef CLIPPING` в одном тексте дают другую программу, и
именно так баг 1.3 и прячется. Один набор — одна сборка.

**R4. Отчёт и аннотации должны нести дефайны.** В `report.json` у каждой цели —
поле `defines`. В аннотации GitHub (`::error file=…,title=…`) набор дефайнов должен быть
в заголовке, иначе по ленте не понять, какой из 32 вариантов `MegaPlanePS` упал. Сейчас
`emit_github_error` заголовок принимает — надо заполнить.

**R5. `--list` показывает дефайны**, и вместе с ними — итоговое число сборок. Отчёт в конце:
`собрано 381 цель, уникальных исходников 147, из них с дефайнами 72`.

**R6. Проверка на дрейф.** Если в таблице дефайнов есть `source`, которого нет на диске —
это ошибка (exit 2), а не тихий пропуск. Так мы поймаем расхождение, если кто-то
переименует файл.

**R7. SM5 — по желанию.** 381 цель на SM4 — это несколько минут. Умножать на два ради
SM5 не стоит: движок просит 4_0 (`HALShaderManager` → `halShader_D3D11::Set`), и SM5
полезен только как раннее предупреждение. Если оставляешь — вынеси в матрицу
`shader_model` и запускай SM5 как отдельный job.

**R8. Не помечать job как `continue-on-error`.** Проверка, которая не блокирует, не
проверка. Если 381 сборка окажется медленной — параллель матрицей по каталогам
(`SpeedTree`, `SMAA`, корень), а не отключением.

## 4. Чего не делать

* **Не править шейдеры, чтобы стало зелёным.** Правки — только там, где fxc находит
  настоящую ошибку, и с объяснением в коммите. Смена семантики ради прохождения CI
  недопустима: ценность CI именно в том, что он ловит расхождение с тем, что грузит игра.
* **Не определять `INTERMEDIATE_FRONDBRANCH_FADING` безусловно** в
  `SpeedTreeDefaults.hlsli` — сейчас он там определён, и это расходится с движком.
  В `SpeedTree2/SpeedTreeDefines.h:11` макрос **закомментирован**, а
  `SpeedTreeForest.cpp:3770` передаёт его с CPU только если включён. Определяя его в
  `.hlsli`, ты включаешь в шейдере fade, параметры которого CPU не присылает. Правильно:
  в `.hlsli` его **не** определять, а в наборе дефайнов он появляется только когда
  собирается вариант «fade on» (сейчас такой вариант не нужен — в движке выключен).
  Тот же критерий для `HORZ_BILLBOARDS`, `BRANCH_DETAIL_LAYER`, `UPVECTOR_POS_Y`:
  `SpeedTreeDefines.h` держит их закомментированными, значит в базовом наборе их быть
  не должно.
* **Не добавлять в базовый набор макросы, которые движок не передаёт.** Их в порте 51 —
  `IDV_OPENGL` (42 файла), `UPVECTOR_POS_Y` (39), `TWO_WEIGHT_WIND` (21), `PSSM` (12),
  `SHADER_TEST` (11), `DEPTH_PASS` (7) и прочие. Это мёртвые ветки legacy-кода; их
  включение — отдельное решение, а не побочный эффект этой задачи.
* **Не трогать `MegaPlaneVS.hlsl` в части алиаса `USE_FOG1`** — он там нужен (мы
  переносили его в `core_dll/shaders/HLSL_D3D11/`, значения совпадают).

## 5. Приёмка

1. `python tools/compile_shaders.py HLSL_D3D11 --list` печатает 381 цель и для каждой —
   её дефайны.
2. Обычный прогон: **381 цель, exit 0**. Время — сообщи фактическое.
3. `report.json` содержит `defines` у каждой цели; в артефакте `.cso` имена различаются
   по набору (как у тебя уже сделано в `output_path`).
4. **Тест на покрытие (главный).** Временно вставить в `MegaPlanePS.hlsl` внутрь блока
   `#ifdef SHADOW` строку `#error shadow variant reached`, прогнать CI, убедиться, что
   **краснеет** ровно вариант `MegaPlanePS` с `SHADOW` (и только он), затем откатить.
   Без этого теста нет доказательства, что дефайны доехали до fxc.
5. То же для `SpeedTree/BillboardsPS.hlsl` с `#ifdef USE_SHADOWS`.
6. CI зелёный на `windows-latest`, job блокирующий.

## 6. Справочно

* `core_dll/docs/shader_engine_defines.json` — готовые 381 запись, копируй в
  `HLSL_D3D11/EngineDefines.json`, если идёшь путём R1-б.
* `core_dll/tools/gen_engine_defines.py` — генератор этой таблицы; если найдешь
  неточность в правилах, правь правила там, а не JSON руками.
* Наш CI в `core_dll` (`.github/workflows/shader-check.yml`) клонирует ваш репозиторий,
  накладывает три файла из `core_dll/shaders/HLSL_D3D11/` и гоняет свой скрипт. Поэтому
  `Shaders.json` должен оставаться валидным: если меняешь формат — скажи, мы подстроимся.
* Из 89 имён `*.cg`, которые движок просит, порта нет у девяти:
  `SMAA_VS`, `SMAA_PS`, `TypeMap`, `TypeMap2D`, `TypeMapPortBump`, `TypeMapPortMult`,
  `TypeMapPortVP` (и два артефакта разбора). SMAA грузится через `SMAA_Passes.hlsl`
  (`HAL/D3D11Probe.cpp:802`), `TypeMap*` — редакторные. В эту задачу не входит, просто
  чтобы не искал.
